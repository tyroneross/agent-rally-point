Headline

File-based shared context works for simple ordered recall: 2/2 fresh agents verbatim. The durable-memory and role-visibility gaps found by research are addressed by five new repo artifacts (charter, modes, retests, simulator + tests, notification schema).

1 · What was found

  • No TEAM.md / CHARTER.md / GOAL.md existed at root or ~/dev depth 2 (16k-file search) — this change adds the first team contract.
  • Canonical durable record is per-repo .rally/log/*.jsonl; facts.db, snapshot.cache.json, claim-index and cursors are disposable. Active engagement pointer lives outside the repo.
  • Rally already records a lead seat (first frontier join or user-designated), ack gate, exclusive file-scope claims with lease expiry, and merge-gate doctrine. It records and exposes; it does not force agents.
  • Stored sessions carry role:null — roles must be derived from live state (rally room / lead show), not persisted as identity.
  • Build-loop durable goals are backlog.md + milestones.jsonl + CURRENT.md (no goal.md API); persona-lab runs plan-only with blind lanes and file:line-verified encounters.
  • Notification precedents exist: monitor.py deltas (last_seq + surfaced keys), per-tool file sinks (consumers.toml), agent-rally.fact.v1 envelope, bookmark trails (trails/files.md, LATEST.md, cost-ledger.jsonl).

3 · Flow of work and comms between agents

  1. Lead authors shared context. Lead writes mission + ordered task list with context_version (canary: /tmp/team-recall-canary.md, checksum ALPHA-BRAVO-CHARLIE-DELTA-7).
  2. Lead spawns members. subagent_spawn with a narrow objective ("read the file, report verbatim starting with RECALL-A/B"); shared workspace, no isolation needed for read-only recall.
  3. Members read, never guess. Each member opens the same file body and quotes it back; no member-to-member channel is used — the file is the single source of truth.
  4. Lead verifies. subagent_wait collects each result; lead diffs order + checksum. Mismatch = fail, not retry-by-editing the check.
  5. Research fans out, then merges. Five workflow children inspect different surfaces (rally store, personas/build-loop, retests, options, notifications) in parallel; a synthesis agent merges compact evidence + unresolved list into one terminal summary.
  6. Steady-state comms use the ledger. rally say artifact → .rally/log/ (status heartbeats every ~10 min, silence >15 min is a coordination bug); team.event.v1 adds role + ack_seq so staleness is detectable; rally room projects lead, mode, and last event per agent.
  7. Change = new version + re-ack. Any mutation to mission or order bumps context_version; members re-ack and re-quote (R3) before merge. Stale-version work fails the merge gate, never the keystroke.

Channels used / deliberately not used

  • Used: subagent_spawn/subagent_wait (task refs), Workflow parallel + synthesis, shared files, .rally/log facts.
  • Present but unused: session-message list/send (2 live peer sessions reachable) — not messaged to avoid interrupting real work; canary used fresh subagents instead.
