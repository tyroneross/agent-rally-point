## Top-3 quick wins

### 1. Path-normalising canonical-claim validator (rank 1, S) — do this first

The sync-10 collision (Claude #2 claiming `src/lib.rs` while Codex held `crates/rally-cli/src/lib.rs`) exposed the substrate's own before-write gate as the source of failure. Raw-string path matching passed a silent double-claim that required manual detection and policy 6 as a workaround. This is the **linchpin**: ranks 2 (auto-lead-assert), 4 (finding-routing), 7 (self-routing), and 8 (ripple-detector) all depend on canonical claim matching to be trustworthy. Without it, the other automations can be fooled by the same path-spelling mismatch that fooled the gate in the first place. Effort is S; the workspace-member scan runs once and caches.

### 2. Auto-Lead-Assert on first enter (rank 2, S)

Once canonical paths are in place, making lead identity a durable room fact is a single atomic write on the existing claim file-lock path. Eliminates the human-maintained-ORCHESTRATION.md dependency for the most foundational coordination fact. Every downstream agent that needs to know who the lead is reads it from the enter response instead of parsing a doc.

### 3. Artifact-significance classifier + filtered stream (rank 3, S)

Two deterministic rules added to the artifact write path (uri-null + sentinel-subject → noise; else → signal). Collapses the lead's per-fact read-and-triage loop across every sync into a filtered subscription. No new storage, no execution surface — pure projection layer.

## Keep human — core decisions

These judgment calls must NOT be automated by rally. Rally may surface information relevant to them, but the ruling is always the lead's, a frontier-agent's, or the user's:

1. **Scope/identity disambiguation** — whether two tool IDs from one process are one agent or two, and deliberate identity splits like `claude_code:lead` vs bare `claude_code` for L4/PR46 (sync 2). Auto-assert records first-in-time; it cannot decide architectural identity splits.

2. **Contested lead succession by capability** — when multiple agents enter near-simultaneously and the right lead depends on capability, context, or user preference. Rally records first-in-time only; which agent *should* lead is a human call.

3. **Collision ownership rulings** — which agent keeps a double-claimed file and which is redirected (sync-10 lib.rs). Rally detects and reports; the redirect is a lead ruling.

4. **Semantic correctness of a fix** — whether a landed fix is correct, sufficient, or introduces a new bug. The normalize_components false positive (sync 17) was caught by reasoning about what the code does, not by pattern-matching. Hash checks and predicate matches cannot substitute.

5. **Re-open vs re-delegate vs accept-with-rationale** — when a grounding check or verify-gate flags an artifact, the disposition is a scope/correctness judgment requiring reading the work.

6. **Cross-lane ripple resolution strategy** — NUL-strip in-place vs change callers vs defer (sync-12 shell_quote ruling), plus sequencing/rebasing across lanes with uncommitted in-flight work. Rally surfaces blast radius; the strategy is the lead's.

7. **Scope/direction forks and novel-architecture calls** — opening new lanes (L5 seam, L6 design), PR46 scope-narrowing (sync 9), A/B tier calibration design and verdict recording. Rally surfaces only what the lead has already encoded.

8. **False-positive adjudication before findings are routed** — unverified findings must never auto-dispatch work. A human or frontier agent marks a finding as confirmed before it enters a routing payload.

9. **Model-tier calibration itself** — running A/B experiments, recording verdicts, approving justified Frontier use for a task that normally runs at Executing, and cross-host tier dictation (rally stops at its own host boundary).

10. **Any irreversible / production action** — push to origin, merge to a shared branch, release tag, schema migration, destructive operation. Explicit lead/user go/no-go required; outside rally's charter entirely.
