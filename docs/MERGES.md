# Merge log — context for every merge to `main`

Now that **commit + merge authority is delegated to frontier agents** (COORDINATION.md field 4), every
merge to `main` MUST append an entry here with **context** — what, *why*, evidence, who, and the lead's
post-hoc audit. This is the durable context record (bookmark-style): a fresh agent or reviewer
understands the history without re-reading diffs, and the lead's audit trail is explicit.

**Entry format (append newest-first):**

```
## <date> · <commit-range> · <subject> — merged by <rally tool-id>
- **Context (why):** <the problem/intent this merge serves>
- **Evidence:** <tests/clippy/fmt/lint or host-equivalent that passed>
- **Lead audit:** ✅ verified <how> | ⚠️ pending | ❌ reverted <reason>
- **Blast radius / reversibility:** <files/systems touched; how to revert>
```

**Rule:** a merge without a MERGES.md entry is incomplete — the lead's post-hoc audit will flag it.
For routine fast-forward pushes of an agent's *own* committed lane, a one-line entry is fine; a
branch→`main` merge (e.g. L4) gets the full entry above.

## 2026-05-29 · R8 replay idempotence — stop destructive rebuild-on-every-open (`store.rs`) · merged by claude_code:01
- **Context (why):** dogfooding surfaced the derived cache (`.rally/facts.db`) being torn down and replayed on **every** `RoomStore::open`. Three compounding root causes in `reconcile_segments_and_db` + `rebuild_db_from_segments`: (1) the rebuild trigger compared `total_count` (raw line count across all segment files) against `db_max_seq` (max sequence number) — only equivalent when seqs are contiguous from 1; (2) the R5 migration monolith `.rally/archive/ledger-pre-segment.jsonl` was both counted and replayed even though its events already live verbatim in the live segments, so every event was double-counted (this repo: **985 raw lines vs 496 distinct events** → `985 > 496` fired a rebuild forever); (3) `rebuild_db_from_segments` asserted `assigned == entry.seq`, which any rotation-induced seq gap breaks. Seq-dedup retained as defense-in-depth.
- **Evidence (red→green):** added 5 tests in `store::ledger_tests`. RED on pre-fix code: `healthy_cache_not_rebuilt_when_count_exceeds_max_seq` (A) + `archived_monolith_excluded_from_replay_no_double_count` (B) failed via inode-canary on `facts.db` (`"...false-triggered a rebuild"` / `"...double-counted..."`); `replay_tolerates_non_contiguous_seqs` (D) failed with `"segment replay seq mismatch: expected 2 got 1"`.
