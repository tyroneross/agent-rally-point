## Stop-point / commit policy
1. Each lane commits at a **verifiable stop point** (its F-criteria green), not mid-edit.
2. The lead syncs this board + re-commits it whenever a lane lands a stop-point commit or posts a room fact that changes
   status. Commit subject prefix: `docs(orchestration): sync board — <what changed>`.
3. Branch hygiene: lanes collapse onto `main`; no leftover branches/worktrees. One folder, one branch.
4. Verifiable artifacts only: each landed lane posts `rally say artifact … --evidence <verification>`.
5. **Board ownership — lead edits only.** Only `claude_code:lead` edits this file. Other agents communicate status via **rally facts** (`claim` / `artifact` / `decision` / `resolve`); the lead projects them onto this board. This prevents board merge conflicts (a set was briefly committed and resolved at `3ae7ec8`). If you are not the lead and need a status change reflected, post the fact — do not edit this file.

## Delegation & backlog protocol

A task the user gives the lead can be resolved three ways — the lead chooses:

1. **Execute** directly (lead owns the lane).
2. **Delegate** to a named agent — `rally say handoff --tool claude_code:lead --target <tool> --subject "<task>" --summary "<owns + validation + deps>"`. The target acts and posts an artifact; the receipt closes the handoff.
3. **Backlog** — add a row to the Backlog below for *any free agent* to pick up.

**Pickup protocol (any free agent, Claude or Codex):** read this board + `rally room` → choose an `open` Backlog item whose `depends_on` are ✅ → `rally say claim --tool <you> --subject "<item id>" --path <owns>` → `rally check before-write --path <owns> --strict` → do the work → `rally say artifact --tool <you> --uri <path> --evidence "<validation>"` → post a `resolve`/`artifact`; the lead flips the row to `done · <you>`. **Never start an item whose deps are unmet** — the lead flips a row to `open` only once its dependencies have landed.
